# 01. 核心概念体系

BizGrow Studio 的核心不是“页面低代码”，而是“业务语义低代码”。

它要解决的问题不是如何快速拖出一个表单，而是如何把业务世界变成可运行、可审计、可被 Agent 推动的结构。

---

## 1. Ontology：业务本体

业务本体定义业务世界中有哪些核心概念。

示例：

```text
客户
订单
产品
BOM
物料
库存
采购需求
生产任务
发货单
应收款
```

本体不是数据库表，也不是知识库文档。

它定义的是：

```text
这个业务世界有哪些核心概念
每个概念是什么意思
它和其他概念有什么关系
它允许发生哪些动作
它有哪些状态和约束
```

---

## 2. Business Object：业务对象

业务对象是本体概念在系统中的落地。

例如：

```text
Order
Customer
Product
Material
Inventory
PurchaseRequest
WorkOrder
DeliveryNote
Receivable
```

业务对象不能只是字段集合，还必须包含：

```text
业务含义
字段定义
可执行动作
可触发事件
生命周期状态
关联对象边界
Agent 可读范围
Agent 可执行范围
人工确认条件
审计要求
```

---

## 3. Semantic Relation：业务语义关系

传统外键表达的是物理关联：

```text
order.customer_id = customer.id
```

BizGrow 表达的是业务语义关系：

```text
Customer places Order
Order contains OrderLine
OrderLine references Product
Product uses BOM
BOM consumes Material
Material affects Inventory
Inventory triggers PurchaseRequest
```

区别：

```text
外键回答：数据怎么连。
语义关系回答：业务为什么这样连，以及变化会影响谁。
```

---

## 4. State Machine：状态机

状态机控制业务对象的生命周期。

例如订单状态：

```text
草稿
待评审
已确认
执行中
已发货
已完成
已取消
```

每个状态转换必须定义：

```text
触发动作
进入条件
退出条件
执行主体
是否允许 Agent 执行
是否需要人工确认
失败补偿动作
```

没有状态机，Agent 只是在聊天。  
有状态机，Agent 才是在业务系统里推进对象。

---

## 5. Rule：业务规则

规则定义系统边界。

基本结构：

```text
WHEN 发生什么事件
IF 满足什么条件
THEN 执行什么动作
```

示例：

```text
WHEN 订单提交评审
IF 订单金额 > 100000
THEN 创建老板审批任务
```

```text
WHEN 库存检查完成
IF 任一物料库存 < 安全库存
THEN 生成采购建议，并要求人工确认
```

规则不是装饰页面，而是运行时判断依据。

---

## 6. Agent Policy：Agent 职责边界

Agent 不是万能员工。

Agent 是被系统边界约束的业务执行器。

每个 Agent 必须定义：

```text
职责
可读取的数据
负责的业务对象
允许执行的动作
禁止执行的动作
必须人工确认的动作
标准输出结果
审计要求
```

示例：订单评审 Agent

```text
可读：订单、客户信用、历史订单、库存摘要
可做：生成评审建议、标记风险、创建人工确认任务
不可做：删除订单、直接确认订单、直接发货
```

---

## 7. Business Loop Template：业务闭环模板

模板不是某个具体订单。

模板是业务路线。

示例：订单驱动型交付闭环模板

```text
客户需求
→ 创建订单
→ 订单评审
→ 库存检查
→ 采购建议
→ 生产任务
→ 发货提醒
→ 完成订单
```

模板定义：

```text
目标
起点
终点
阶段
每个阶段绑定的对象
每个阶段的执行主体
每个阶段的规则
每个阶段的 Agent 权限
每个阶段的人工确认条件
```

---

## 8. Business Loop Instance：业务闭环实例

这是 BizGrow 的核心运行概念。

它不是客户，不是订单，不是产品，不是采购需求。

它是：

> 一次业务目标的完整执行现场。

示例：

```text
BR-2026-0001
目标：完成华东电梯厂定制订单交付
当前节点：订单评审
当前状态：Agent 执行中
主对象：订单 OR-2026-001
关联对象：客户、产品、BOM、物料、库存、采购需求、生产任务、发货单、应收款
```

一句话：

```text
业务对象是零件。
业务闭环模板是路线。
业务闭环实例是一次真实运行。
Agent 是推进器。
审计日志是可追责轨迹。
```

---

## 9. Task：任务

任务中心承接系统运行中的人工动作。

任务来源包括：

```text
规则触发
Agent 申请
状态机阻塞
系统异常
人工转办
```

任务不是普通待办，而是业务闭环实例中的控制点。

---

## 10. Audit Log：审计日志

审计日志记录每一次业务推进。

必须记录：

```text
谁触发
什么时候触发
读了哪些数据
命中了哪些规则
Agent 做了什么判断
执行了什么动作
是否经过人工确认
动作结果是什么
```

没有审计日志，Agent 不能进入真实业务系统。
