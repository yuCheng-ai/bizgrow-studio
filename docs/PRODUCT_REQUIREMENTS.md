# BizGrow Studio 产品需求文档 v0.1

## 1. 产品目标

BizGrow Studio 是面向企业业务系统的元建模与运行平台。

最低目标：

```text
简道云能做的基础低代码能力，BizGrow Studio 都应该能做。
但 BizGrow Studio 不能沿用大宽表、弱关联、流程脚本堆叠的底层路线。
```

核心目标：

```text
让企业可以从对象、关系、动作、状态、规则和视图出发，持续搭建和演进业务系统。
```

产品不是只解决“一期快速交付”，而是要支持业务系统继续迭代到二期、三期、四期后仍然可维护。

## 2. 目标用户

### 2.1 内部实施人员

负责为客户搭建业务系统。

他们需要：

- 设计对象
- 设计字段
- 设计表单
- 配置关系
- 配置动作
- 配置生命周期
- 配置规则
- 生成运行端页面
- 发布配置
- 排查运行问题
- 通过 Codex / MCP 让 AI 代劳部分配置工作

### 2.2 企业业务管理员

负责客户侧业务系统维护。

他们需要：

- 调整表单
- 调整字段
- 管理权限
- 查看审批和任务
- 查看运行日志
- 修改轻量规则
- 查看数据和报表

第一版不建议让客户直接接触全部元模型能力。高级配置应优先由内部实施人员使用。

### 2.3 企业业务用户

最终使用运行端系统的人。

他们需要：

- 填表
- 查数据
- 提交审批
- 处理任务
- 查看详情
- 根据权限操作对象
- 使用 Agent 辅助完成业务

## 3. 产品分层

BizGrow Studio 至少分为两端。

### 3.1 配置端

面向实施人员和高级管理员。

职责：

- 定义对象
- 定义字段
- 定义关系
- 定义动作
- 定义状态
- 定义规则
- 定义视图
- 定义权限
- 定义 Agent 能力
- 发布配置
- 暴露受控 MCP 能力，让 Codex 可以读取元模型、生成配置草稿、提交变更建议

### 3.2 运行端

面向企业业务用户。

职责：

- 使用列表、表单、详情、审批、任务、仪表盘
- 执行业务动作
- 查看对象关系和运行记录
- 使用 Agent 建议

配置端是系统生成器，运行端是客户真正使用的业务系统。

### 3.3 Codex MCP 协作层

面向 Codex、IDE Agent、内部自动化工具。

职责：

- 读取对象、字段、关系、动作、规则、视图等元模型
- 根据自然语言生成配置草稿
- 批量创建字段、表单、规则和视图草稿
- 运行配置校验
- 输出影响分析
- 生成测试样例
- 提交待审核变更

边界：

- MCP 不能直接发布配置
- MCP 不能绕过权限
- MCP 不能直接修改运行态业务数据
- MCP 的每次工具调用必须写入审计
- 高风险变更必须人工确认

## 4. 能力分级

优先级定义：

```text
P0：MVP 必须实现，否则产品不成立
P1：第一版应实现，影响完整度
P2：后续增强，影响竞争力
P3：远期能力，暂不进入第一阶段
```

## 5. P0 需求

### 5.1 对象类型管理

目标：

支持创建业务对象类型，并作为所有配置的根。

功能：

- 创建对象类型
- 编辑对象名称、编码、描述、分类
- 设置主显示字段
- 查看对象下的字段、关系、动作、状态、规则、视图
- 禁用或归档对象

验收标准：

- 可以创建一个新对象类型
- 可以给对象增加字段
- 可以在运行端基于对象创建实例
- 对象不能在有运行数据时被直接删除

### 5.2 字段模型

目标：

支持对象字段配置，覆盖传统低代码表单字段能力。

字段类型：

- 文本
- 长文本
- 数字
- 金额
- 日期
- 日期时间
- 枚举
- 布尔
- 引用对象
- 文件
- JSON
- 状态

功能：

- 设置字段名称、编码、类型
- 设置必填、唯一、默认值
- 设置校验规则
- 设置字段权限
- 设置 Agent 访问权限
- 查看字段被哪些视图、规则、动作引用

验收标准：

- 字段可以被表单使用
- 字段可以被列表展示
- 字段可以被规则引用
- 字段删除前必须提示引用影响

### 5.3 表单设计

目标：

覆盖简道云类表单搭建能力，但表单必须绑定对象。

功能：

- 拖拽字段到表单
- 设置分组、布局、提示文案
- 设置字段显隐
- 设置字段只读
- 设置必填校验
- 预览表单

验收标准：

- 可以基于对象字段生成表单
- 表单提交会创建或更新对象实例
- 表单提交必须走对象动作
- 表单不能直接绕过权限和规则写数据

### 5.4 列表视图

目标：

支持对象数据的基础管理。

功能：

- 配置列表字段
- 配置筛选条件
- 配置排序
- 配置搜索字段
- 配置行操作
- 配置批量操作

验收标准：

- 可以查看对象实例列表
- 可以按字段筛选
- 可以点击进入详情
- 列表操作必须绑定对象动作

### 5.5 详情页

目标：

详情页不是简单字段展示，而是对象运行状态的聚合页。

功能：

- 展示对象字段
- 展示当前状态
- 展示可执行动作
- 展示关联对象
- 展示规则命中记录
- 展示操作日志
- 展示审批和任务

验收标准：

- 从列表可以进入详情页
- 详情页能看到对象关系
- 详情页能执行动作
- 动作执行后能看到审计记录

### 5.6 对象关系

目标：

支持对象间语义关系，不只是引用字段。

功能：

- 配置源对象和目标对象
- 配置关系类型
- 配置一对一、一对多、多对一、多对多
- 配置关系方向
- 配置影响范围
- 在详情页展示关联对象

验收标准：

- 可以创建对象间引用关系
- 可以在详情页看到关联数据
- 可以在规则和 Agent 上下文中读取关系
- 关系删除前必须提示影响

### 5.7 对象动作

目标：

所有核心数据变化必须通过动作。

功能：

- 创建动作
- 设置动作输入
- 设置动作权限
- 设置动作效果
- 设置是否需要确认
- 绑定前置规则
- 绑定后置规则

验收标准：

- 表单提交走动作
- 按钮操作走动作
- 审批通过走动作
- Agent 发起执行也走动作
- 动作执行必须写审计

### 5.8 生命周期

目标：

支持对象状态流转。

功能：

- 定义状态
- 定义初始状态
- 定义终态
- 定义状态流转
- 将流转绑定动作
- 将规则作为流转守卫

验收标准：

- 对象可以拥有生命周期
- 状态流转必须通过动作
- 不允许规则绕过动作直接改状态
- 状态变化必须记录事件

### 5.9 规则构件库

目标：

提供业务无关的规则表达积木。

功能：

- 管理触发器构件
- 管理条件构件
- 管理逻辑构件
- 管理动作构件
- 定义参数 Schema
- 查看构件示例

验收标准：

- 规则构件不绑定具体业务对象
- 业务规则实例可以引用规则构件
- 构件修改需要版本化

### 5.10 业务规则实例

目标：

支持对象、动作、状态上的规则配置。

功能：

- 选择触发时机
- 配置判断条件
- 配置执行动作
- 查看引用字段
- 查看影响动作
- 查看 DSL JSON
- 试运行测试
- 发布规则

验收标准：

- 规则能在动作请求时命中
- 规则能阻断动作
- 规则能要求审批
- 规则能写审计日志
- 规则命中过程可追踪

### 5.11 权限

目标：

支持企业基础权限。

功能：

- 对象权限
- 字段权限
- 视图权限
- 动作权限
- 规则发布权限
- Agent 调用权限

验收标准：

- 不同角色看到不同字段和动作
- 无权限用户不能执行动作
- Agent 不能越权读取或执行

### 5.12 审计日志

目标：

所有关键操作可追踪。

功能：

- 记录对象创建、修改、删除
- 记录动作请求和执行
- 记录规则检查和命中
- 记录审批
- 记录 Agent 调用
- 支持按对象、用户、规则、执行链路查询

验收标准：

- 任意一次动作执行能看到完整审计
- 规则为什么命中或没命中可解释
- Agent 参与过的操作必须可追踪

## 6. P1 需求

### 6.1 审批与任务

功能：

- 创建审批任务
- 指派角色或用户
- 审批通过
- 审批拒绝
- 审批意见
- 超时提醒

验收标准：

- 规则可以要求审批
- 审批通过后动作继续执行
- 审批拒绝后动作阻断

### 6.2 发布管理

功能：

- 保存草稿
- 静态校验
- 影响分析
- 发布版本
- 回滚版本
- 比较版本差异

验收标准：

- 未发布配置不影响运行端
- 发布前能发现字段和规则引用错误
- 运行记录能关联配置版本

### 6.3 仪表盘

功能：

- 基于对象统计数据
- 基于动作统计数据
- 基于状态统计数据
- 基于规则命中统计
- 自定义图表

验收标准：

- 可以配置一个对象统计卡片
- 可以配置一个列表型报表
- 可以查看规则命中趋势

### 6.4 导入导出

功能：

- Excel 导入对象实例
- Excel 导出对象实例
- 配置包导入
- 配置包导出

验收标准：

- 导入时走字段校验
- 导入错误可下载
- 配置包能跨环境迁移

### 6.5 Agent 辅助配置

功能：

- 根据自然语言生成字段建议
- 根据自然语言生成规则草稿
- 解释规则 DSL
- 分析字段影响范围
- 生成测试样例

验收标准：

- Agent 生成内容必须是草稿
- 草稿必须经过人工审核才能发布
- Agent 生成规则必须通过系统校验

### 6.6 Codex MCP 配置协作

目标：

配置端需要提供原生 MCP 能力，让 Codex 可以作为实施助手参与系统搭建。

功能：

- MCP 读取本体包
- MCP 读取对象类型
- MCP 读取字段、关系、动作、生命周期、规则、视图
- MCP 创建配置草稿
- MCP 批量生成字段
- MCP 批量生成表单视图
- MCP 生成规则 DSL 草稿
- MCP 运行配置校验
- MCP 生成影响分析
- MCP 提交变更建议
- 配置端可以为项目生成 MCP 项目 Key
- 用户可以生成或授权个人身份 Key
- 系统可以将项目 Key 和用户身份 Key 合并为一次 AI 操作授权 Key

验收标准：

- Codex 可以通过 MCP 获取当前配置上下文
- Codex 可以根据需求生成对象、字段、表单、规则草稿
- Codex 生成的内容不能直接发布
- Codex 生成的内容必须进入人工审核和发布流程
- 所有 MCP 调用必须有调用日志和审计记录
- MCP 权限必须受当前用户或服务账号限制
- 每次 MCP 调用都必须能识别所属项目
- 每次 MCP 调用都必须能识别授权用户
- 系统必须能追踪是哪一个用户授权 Codex 对哪一个项目进行操作
- MCP 授权 Key 必须支持过期、吊销和权限范围限制

## 9. 第一版 MVP 范围

建议第一版只做以下闭环：

```text
配置端：
对象类型
字段模型
表单视图
列表视图
详情视图
对象动作
规则构件
业务规则实例
权限
发布

运行端：
对象列表
对象详情
表单提交
动作执行
规则阻断
审批任务
审计日志
```

第一版必须跑通：

```text
创建对象 -> 配字段 -> 配表单 -> 配动作 -> 配规则 -> 发布 -> 创建实例 -> 执行动作 -> 规则命中 -> 审批或阻断 -> 审计可查
```

第一版增强目标：

```text
Codex 通过 MCP 读取元模型 -> 生成配置草稿 -> 系统校验 -> 人工审核 -> 发布
```

## 10. 核心验收场景

### 场景 1：搭建一个普通表单应用

验收：

- 可以创建对象
- 可以配置字段
- 可以配置表单
- 可以录入数据
- 可以列表查看
- 可以详情查看

这是覆盖简道云基础能力的最低门槛。

### 场景 2：搭建一个有关联的业务应用

验收：

- 可以创建两个对象
- 可以配置对象关系
- 可以在表单中选择关联对象
- 可以在详情页查看关联数据
- 可以基于关联数据做规则判断

这是证明我们不是弱关联表单系统。

### 场景 3：动作驱动状态流转

验收：

- 可以定义对象状态
- 可以定义提交动作
- 可以将动作绑定状态流转
- 执行动作后状态变化
- 状态变化有审计

这是证明我们不是普通字段更新系统。

### 场景 4：规则阻断动作

验收：

- 可以定义规则
- 动作执行前规则被检查
- 条件满足时动作被阻断或要求审批
- 规则命中日志可查看

这是证明规则 DSL 能进入运行链路。

### 场景 5：Agent 生成规则草稿

验收：

- 用户输入自然语言规则
- Agent 生成 DSL 草稿
- 系统校验 DSL
- 人工审核发布
- 发布后规则能命中

这是证明 Agent 不是聊天装饰，而是参与配置生产。

### 场景 6：Codex 通过 MCP 代劳配置

验收：

- Codex 可以读取当前对象和字段模型
- 用户描述一个新业务对象或规则
- Codex 通过 MCP 创建配置草稿
- 系统返回校验结果和影响分析
- 实施人员在配置端审核
- 审核通过后再发布

这是证明配置端不仅给人用，也能被 AI 工具安全地调用。

## 11. 非目标

第一版不做：

- 完整 ERP
- 完整 CRM
- 完整 BPMN
- 任意脚本平台
- 复杂图数据库推理
- 完整 OWL 推理
- Agent 自动改核心数据
- 面向所有行业的模板市场
- MCP 直接发布配置
- MCP 直接修改运行态业务数据

## 12. 关键产品判断

BizGrow Studio 要避免两个极端：

```text
只做传统低代码：没有壁垒，后期也会陷入大宽表和弱关联问题。
只做抽象元系统：客户看不懂，第一版无法落地。
```

正确路径：

```text
用传统低代码能力作为入口。
用对象元模型作为底座。
用规则 DSL 和动作系统保证长期演进。
用 Agent 提升配置效率，但不破坏运行确定性。
```
