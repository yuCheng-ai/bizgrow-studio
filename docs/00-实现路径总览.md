# 00. BizGrow Studio 实现路径总览

## 1. 系统定位

BizGrow Studio 是一个 **本体驱动的语义低代码业务运行系统**。

它不是传统拖拽低代码，也不是普通 BPM / OA / ERP。它的目标不是让用户拖表单、拖流程、拖按钮，而是让用户定义业务语义，系统自动生成可运行的业务闭环。

核心表达：

```text
先定义业务世界
→ 再生成业务系统
→ 最后由受控 Agent 推动业务运行
```

## 2. 核心链路

```text
业务本体
→ 业务对象
→ 关系图谱
→ 状态机
→ 业务规则
→ Agent 边界
→ 业务闭环模板
→ 业务闭环实例
→ 任务中心
→ 审计日志
```

## 3. 和传统系统的差异

传统系统以表和模块为中心：

```text
模块 → 页面 → 表 → 外键 → 查询 → 审批流
```

BizGrow 以业务语义和运行实例为中心：

```text
本体 → 对象 → 关系图谱 → 状态机 → 规则 → Agent → 业务闭环实例
```

传统系统知道表之间怎么关联，但通常不知道业务为什么这样流转。BizGrow 要把业务流转原因、动作边界、规则命中、人工确认和审计轨迹显式建模。

## 4. 最核心的新概念

### 业务闭环实例 Business Loop Instance

它不是订单，不是客户，不是采购需求。

它是一次业务目标的完整执行现场。

例如：

```text
BR-2026-0001
目标：完成华东电梯厂定制订单交付
当前节点：订单评审
主对象：订单 OR-2026-001
关联对象：客户、产品、BOM、物料、库存、采购需求、生产任务、发货单、应收款
```

一句话：

```text
对象是零件。
模板是路线。
业务闭环实例是一次真实运行。
Agent 是推进器。
审计日志是可追责轨迹。
```

## 5. 不要做成什么

第一版不要做：

```text
全行业通用平台
复杂拖拽画布
自动生成完整 ERP
全自动 Agent 决策
复杂图数据库推理
复杂组织权限系统
真实财务/采购/ERP 深度集成
```

否则会快速变成 PPT。

## 6. 第一版只打穿一个闭环

第一版只做：

```text
订单评审
→ 库存检查
→ 采购建议
→ 人工确认
→ 生产任务
```

验收标准：

```text
1. 可配置业务对象：Order / Material / Inventory / PurchaseRequest / WorkOrder
2. 可配置关系：Order → BOM → Material → Inventory
3. 可配置状态机
4. 可配置规则
5. 可配置 Agent 边界
6. 可生成业务闭环模板
7. 可生成业务闭环实例 BR-2026-0001
8. 库存不足时生成采购建议
9. 采购建议必须人工确认
10. 人工确认后生成生产任务
11. 全过程写审计日志
```

## 7. 实施阶段

### Phase 0：概念原型

当前阶段。目标是让别人看懂产品不是传统低代码。

### Phase 1：BizDSL 编辑器 + 编译器

让业务语义能被结构化表达、校验、版本化。

### Phase 2：BizRuntime 运行时 MVP

从模板生成业务闭环实例，并让实例真的跑起来。

### Phase 3：受控 Agent 执行

Agent 在权限边界内读取、判断、生成建议、创建任务，关键动作必须人工确认。

### Phase 4：真实业务接入

接 Excel、ERP、API、Webhook、SOP 文档等真实数据源。

### Phase 5：多场景复用

从订单交付扩展到采购、售后、合同、回款、项目交付。

## 8. 当前优先级

最高优先级不是继续做前端页面，而是沉淀三件事：

```text
BizDSL
BizRuntime
Business Loop Instance
```

没有 DSL，系统会碎成一堆配置表单。  
没有 Runtime，系统只是页面原型。  
没有 Business Loop Instance，系统无法区别模板和真实运行。
