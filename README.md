# BizGrow Studio

BizGrow Studio 是一个基于「本体论驱动」的语义低代码 Agent 业务运行系统原型。

核心设计理念：

> 先定义业务世界，再生成业务系统，最后由受控 Agent 推动业务运行。

当前阶段主要完成纯前端展示与产品概念验证，不包含真实后端、登录鉴权体系及真实 AI API 调用。后续系统内核会围绕 `BizDSL`、`BizRuntime` 与 `Business Loop Instance` 逐步实现。

---

## 项目定位

传统业务系统通常以模块、页面、数据表和外键为中心：

```text
模块 → 页面 → 表 → 外键 → 查询 → 审批流
```

BizGrow Studio 的目标不是做一个普通拖拽式低代码平台，而是把业务世界描述为：

```text
业务本体
→ 业务对象
→ 关系图谱
→ 状态机
→ 业务规则
→ Agent 边界
→ 业务闭环模板
→ 业务闭环实例
→ 任务中心
→ 审计日志
```

核心差异：

- **不是表驱动，而是本体驱动**：先定义客户、订单、产品、BOM、物料、库存、采购需求等业务概念。
- **不是外键拼业务，而是语义关系图谱**：表达 `Order uses BOM`、`BOM consumes Material`、`Inventory triggers PurchaseRequest` 这类业务关系。
- **不是流程图优先，而是业务闭环模板优先**：流程图只是渲染结果，不是主要编辑入口。
- **不是 Agent 自由发挥，而是受控 Agent**：每个 Agent 都有可读数据、可执行动作、禁止动作和人工确认边界。
- **不是简单自动化，而是可审计运行**：每次规则命中、Agent 判断、人工确认和系统动作都要可追踪。

## 核心概念

### BizDSL

业务语义 DSL，用于定义业务对象、关系、状态机、规则、Agent 权限和业务闭环模板。

### BizRuntime

业务语义运行时，用于解释 DSL 生成的模型，创建业务闭环实例，并推进实例运行。

### Business Loop Instance

业务闭环实例。它不是订单，也不是客户，而是一次业务目标的完整执行现场。

例如：

```text
BR-2026-0001
目标：完成华东电梯厂定制订单交付
当前节点：订单评审
主对象：订单 OR-2026-001
关联对象：客户、产品、BOM、物料、库存、采购需求、生产任务、发货单、应收款
```

一句话：

```text
对象是零件。
模板是路线。
业务闭环实例是一次真实运行。
Agent 是推进器。
审计日志是可追责轨迹。
```

## 当前原型模块

1. **总览 Dashboard**：展示业务大盘、系统生成链路、业务闭环模板与运行实例。
2. **业务本体 Ontology**：定义商业模式中的核心概念实体。
3. **业务对象 Object**：将本体落成可被系统控制、被 Agent 读写的业务对象。
4. **关系图谱 Relation**：表达对象之间的业务语义关系，而不是单纯外键关系。
5. **状态机 State**：定义业务对象生命周期及其状态转换条件。
6. **流程编排 Process**：展示业务闭环模板，不以拖拽画布为核心。
7. **规则引擎 Rule**：配置 `WHEN / IF / THEN` 业务规则。
8. **Agent 配置 Agent**：定义 Agent 职责、可读数据、允许动作、禁止动作和人工确认条件。
9. **任务中心 Task Center**：承接规则、系统、Agent 触发的人工确认和异常处理任务。
10. **审计日志 Audit Log**：记录每一次业务流转、规则命中、Agent 动作、人工确认和数据修改。

## MVP 落地目标

第一版不要做全行业通用平台，只打穿一个最小业务闭环：

```text
订单评审
→ 库存检查
→ 采购建议
→ 人工确认
→ 生产任务
```

如果这条链能基于 DSL、规则、状态机、Agent 边界、任务中心和审计日志真实运行，项目就从前端 demo 进入产品内核阶段。

## 开发与运行方式

本项目当前采用纯前端 Mock 技术栈，以 `TypeScript`, `React`, `Vite` 构建，并使用 `Tailwind CSS` 与 `lucide-react` 提供核心视觉系统。

```bash
# 1. 安装依赖
npm install

# 2. 本地开发服务器，运行在 3000 端口
npm run dev

# 3. 类型检查与代码校验
npm run lint

# 4. 构建生产环境产物
npm run build
```

运行约束：

- `npm run dev` 已经限定通过 `host=0.0.0.0` 和 `port=3000` 启动服务。

## 目录结构

- `src/components/`：前端可视化界面及各个业务面板的核心组件。
- `src/components/common/`：基础 UI 组件，如 `PageHeader`, `Card`, `StatusBadge`。
- `src/data/`：Mock 数据，根据模块拆分，便于独立迭代。
- `src/types.ts`：TypeScript 接口，定义本体、业务状态、规则、Agent、执行日志等核心对象。
- `docs/`：产品、架构、DSL、运行时与 MVP 实现路线文档。

## 当前阶段判断

当前项目还不是完整产品，而是产品概念和前端原型。

下一阶段重点不是继续堆页面，而是实现三件事：

```text
BizDSL 编辑器
BizDSL 编译校验器
BizRuntime 最小运行时
```

只有这三件事做出来，BizGrow Studio 才开始拥有真正的产品内核。
